# Approach

The service was implemented in Next.js 16 (App Router), Supabase (Postgres), and Anthropic Claude for LLM classification, selected for rapid iteration, zero, config Vercel deployment, and native structured JSON output from LLM. Content extraction is done by Mozilla Readability (the same engine behind Firefox Reader View) combined with jsdom which provided accurate article parsing without having to train a custom model. Zod is used for runtime validation at each API boundary and on LLM output, ensuring that malformed responses are caught before being stored in the database.

Claude Code has been used as a pair programming tool during the whole development. I guided the architecture, prompt engineering, security decisions (SSRF protection, prompt injection defense, rate limiting), and test design, while Claude Code helped the implementation by drafting boilerplate, generating test scaffolding, and handling repetitive edits across files. We always reviewed, tested, and often revised every single piece of generated code, the classifier prompt, for example, went through three iterations after live testing revealed misclassification of off, topic content.

The major trade, off was polling instead of streaming for progress feedback: POST returns 202 immediately and the UI polls every 2 seconds. Server, Sent Events would remove the delay between requests, however, polling works through all proxies and CDNs without any infrastructure changes, the right call for a time, boxed deliverable. Similarly, the in, memory rate limiter is not going to work for the multi, instance (it would require Redis), but it keeps the dependency count low and the interface is designed for a drop, in replacement. Besides that, I abandoned a planned Swagger/OpenAPI integration after realizing that it was overkill for only six endpoints, the README documents every route with curl examples instead.
