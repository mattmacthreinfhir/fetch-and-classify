# Approach

The service was built with **Next.js 16** (App Router), **Supabase** (Postgres), and **Anthropic Claude** for LLM classification — chosen for fast iteration, zero-config Vercel deployment, and native structured JSON output from the LLM. Content extraction uses **Mozilla Readability** (the same engine behind Firefox Reader View) paired with **jsdom**, which gave reliable article parsing without training a custom model. **Zod** handles runtime validation at every API boundary and on LLM output, catching malformed responses before they reach the database.

Claude Code (Anthropic's AI coding assistant) was used throughout development as a pair-programming tool. The architecture, prompt engineering, security decisions (SSRF protection, prompt injection defense, rate limiting), and test design were directed by me; Claude Code accelerated the implementation by drafting boilerplate, generating test scaffolding, and handling repetitive edits across files. Every piece of generated code was reviewed, tested, and often revised — the classifier prompt alone went through three iterations after live testing revealed misclassification of off-topic content.

The main trade-off was **polling over streaming** for progress feedback: POST returns 202 immediately and the UI polls every 2 seconds. Server-Sent Events would eliminate the latency gap, but polling works behind all proxies and CDNs with zero infrastructure changes — the right call for a time-boxed deliverable. Similarly, the **in-memory rate limiter** won't survive multi-instance scaling (it would need Redis), but it keeps the dependency count low and the interface is designed for a drop-in replacement. I also cut a planned Swagger/OpenAPI integration after recognising it was over-engineering for six endpoints — the README documents every route with curl examples instead.
